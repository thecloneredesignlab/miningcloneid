# Manuscript Legend Writing

## Purpose

Produce or validate journal-facing figure legends based on an existing set
of manuscript ready figures and their metadata. This skill owns legend prose, legend
assembly, and legend validation. It does not draft Results text, regenerate
figures, remap evidence, rerun analyses, or perform
manuscript-wide integration.

## Artifact Contract

Required artifact:

- A set of manuscript figures or panels with enough metadata to trace each panel
  back through its generating artifacts and transformations.

The metadata may be supplied as manifests, package provenance files, 
semantic notes, package inventories, scripts, configs, saved tables, or another
equivalent figure package. Do not require a specific file layout when the same
trace facts are available another way. If the required figure/panel + metadata
package cannot identify the requested panel or cannot support a trace through 
generating artifacts and transformations, report
the gap instead of inventing provenance.

Optional artifacts:

- User feedback, instructions, corrections, or scope constraints.
- Existing outputs generated by this skill.
- Semantic interpretation of figure contents.


## Output Contract

Default outputs live in the integration root unless the user specifies another
root:

```text
<integration_root>/
  integrated_figure_legends.md
  feedback_manager_context.md
  legend_revisions/
    Figure_1.md
    Figure_S9.md
  legend_validation_report.md
```

`integrated_figure_legends.md` is the renderer-facing contract:

```markdown
# Figure Legends

## Figure 1. <short title>
<journal-facing legend body>

## Figure S1. <short title>
<journal-facing legend body>

```

Contract rules:

- Include exactly one `##` block for every rendered figure image in
  `figure_set_manifest.csv`.
- Use stable main-then-supplement order from the manifest or crosswalk.
- Give every block a nonempty short title and nonempty body.
- Keep audit, provenance, source paths, commands, and workflow notes out of the
  integrated legend body.
- If per-figure `legend_revisions/*.md` files contain audit notes, merge only
  journal-facing legend text into `integrated_figure_legends.md`.

## Writing Workflow

1. Build the figure list from the input; record expected
   labels before writing.
2. Read instructions/feedback, identify and note any points of relevance for legend writing.
3. For each figure, determine whether it's legend needs to be written, revised,
   or requires no action. 
4. If more than one figure legend needs writing or heavy revision and subagents
   are available and permitted, use subagents in waves. Prefer one rendered
   figure legend block per subagent with a disjoint output such as
   `legend_revisions/Figure_3.md`. Group multiple blocks only for tightly coupled
   figures in audit notes or `legend_validation_report.md`.
5. Require each subagent to write a complete figure legend plus separate audit
   notes when needed. The central agent merges only journal-facing legend text.
6. Assemble `integrated_figure_legends.md` in the contract format.
7. Write `legend_validation_report.md` with pass/block status, expected figure
   count, present legend count, missing/extra labels, source files inspected,
   optional guardrails inspected or unavailable, accepted exceptions, and
   unresolved legend decisions.
8. Revisit feedback items and confirm the work done fully addressed all
feedback within the scope of legend writing/assembly/revision before returning.

## Legend Standard

For each figure, make the legend understandable without the main text while
avoiding a mini-Methods or duplicate Results section. Use figure metadata + 
semantic interpretations as context to understand the contents of the figure.

Include:

- Figure number and short title or summary.
- Panel-by-panel descriptions in panel order.
- Definitions of symbols, colors, lines, abbreviations, units, scale bars, and
  error bars where relevant.
- Statistical essentials where relevant: what intervals/error bars show, sample
  size or `n`, test used, and significance notation.
- Only enough method detail to interpret the figure.
- Necessary scope labels, such as excluded cohort versus full cohort, when the
  figure uses a subset or sensitivity analysis.
- Caveats needed to read the figure correctly, such as model-implied latent
  states versus direct measurements.

Exclude:

- Source roots, generation commands, source legend paths, checksums, revision
  notes, and workflow labels.
- Long procedural detail that belongs in Methods.
- Repeated Results interpretation that is not needed to read the figure.
- Claims stronger than the visible figure content, semantic interpretations,
  upstream approved legend text, or optional guardrails support.

## Validation

Before finishing, check:

- `integrated_figure_legends.md` exists and parses into one block per expected
  figure.
- No expected figure is missing and no extra figure labels are present.
- Figure labels map to manifest/final-image IDs, including continued and
  letter-suffixed supplemental figures.
- Every manifest panel for each figure is described or an omission is documented
  in `legend_validation_report.md`.
- Titles and bodies are nonempty and journal-facing.
- Internal project jargon, source paths, commands, and provenance are absent
  from legend bodies.
- Optional guardrails were checked when present, and any relevant caveats or
  unresolved decisions were handled or recorded.
- Feedback-manager handoff, when present, was reflected in the legend work or
  recorded as blocked/not applicable in `legend_validation_report.md`.
- Legend output does not contain Results prose sidecar material, claim-graph
  edits, section assessment edits, or new analysis claims.
