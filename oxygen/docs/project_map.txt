What the ploidyOxygen workflow already does
- Reconstructs 2N and 4N lineage histories across passages and oxygen changes.
- Associates each passage with:
  - observed growth rate when available
  - binned flow cytometry when available
  - reassigned karyotype summaries when available
- Serializes lineage-aware simulation jobs:
  - jobs_2N.Rds
  - jobs_4N.Rds
- Encodes the in vitro oxygen history explicitly as passage-to-passage trajectories, rather than as a small set of independent conditions.

Interpretation of the current exercise
- The intended scientific direction is no longer the old coarse DEoptim workflow.
- The intended target is the MAP oxygen supply-demand model.
- The available in vitro data assembly currently lives in ploidyOxygen and was built around a separate standalone buffering workflow.
- Therefore the project is currently split across:
  - model/fitter infrastructure in oxygen/code/O2_supply_demand_MAP
  - in vitro lineage data engineering in oxygen/ploidyOxygen

Main gap to close
- The MAP fitter is currently organized around the in vivo data interface.
- The in vitro lineage data are prepared in a different shape and with different assumptions.
- The next technical task is to define an adapter layer that lets the MAP model consume the ploidyOxygen in vitro objects, or regenerate equivalent MAP-ready inputs from the same underlying in vitro lineage information.

Likely near-term tasks
- Inspect the MAP fitter input contract in detail:
  - required scenario structure
  - burden/ploidy likelihood expectations
  - parameter/config requirements
- Inspect the ploidyOxygen fit objects in detail:
  - exact contents of fit_data.Rds
  - exact semantics of jobs_2N/jobs_4N
  - oxygen units and lineage traversal assumptions
- Decide how to represent in vitro observations for the MAP objective:
  - growth only
  - terminal ploidy only
  - lineage-level sequential ploidy fits
  - optional flow-based likelihood later
- Build the smallest working bridge:
  - either a new in vitro MAP fitting script
  - or a mode inside the existing MAP fitter that accepts ploidyOxygen-derived inputs

Current status summary
- Data side: partially prepared for in vitro lineage fitting in ploidyOxygen.
- Model side: newer MAP oxygen supply-demand model exists and is likely the correct target.
- Integration side: a first end-to-end in vitro adapter/objective workflow now exists under oxygen/code/in-vitro-utils and oxygen/workflow.
- Current workflow behavior:
  - `sample_invitro_objective_once.R` samples a transformed start point, runs a short local optimization, and appends the optimized result to a shared timestamped TSV.
  - `simulation_basics.Rmd` loads the best available sampled optimization result (defaulting to the newest timestamped TSV) and visualizes the resulting single-lineage demo run plus the full multi-lineage objective fit.
- Immediate project goal: use this first end-to-end bridge to explore parameter fits and decide what objective/data refinements are needed next.
